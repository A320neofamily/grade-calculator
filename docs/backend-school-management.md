# 학교 삭제 및 JSON 가져오기: 백엔드 확인 사항

## 현재 구성과 확인 범위

이 저장소에는 React 프런트엔드만 있고 Cloudflare Worker 소스나 DB 스키마는 없습니다.
현재 Firebase Google 로그인 토큰을 사용해 기존 Worker API에 요청합니다.
따라서 실제 삭제 실패 원인은 Worker 로그와 브라우저 Network에서 확인해야 하며,
여기서 백엔드 라우트·권한·DB를 수정하거나 실제 서버 삭제를 검증하지는 않았습니다.

프런트엔드에서는 브라우저 `confirm()` 대신 명시적인 삭제 확인창을 사용하고,
중복 요청을 방지하며, 실패 시 데이터를 유지합니다. 삭제 성공 시 관리 목록·
메인 검색 목록·임시로 연 학교·해당 학교의 이 기기 점수를 함께 제거합니다.
`내 목록에서만 제거`는 서버 삭제와 별개의 로컬 작업입니다.

## 1. DELETE 라우트 구현

요청:

```http
DELETE /api/schools/{schoolKey}
Authorization: Bearer <Firebase ID token>
```

- `schoolKey`는 `학교코드-학년-학기`입니다. 생성·조회·수정·삭제가 모두 같은 키를 사용해야 합니다.
- OPTIONS를 인증 처리보다 먼저 처리하고, DELETE가 조회용 와일드카드나 HTML fallback에 잡히지 않게 하세요.
- Firebase Admin SDK 또는 검증된 JWT 라이브러리로 서명·만료·issuer·audience를 검증하세요.
- 토큰의 UID가 작성자 UID 또는 서버에서 지정한 관리자 UID일 때만 삭제하세요.
- 생성 시 인증 토큰에서 얻은 작성자 UID를 DB에 저장하세요. 클라이언트가 보낸 UID를 신뢰하지 마세요.
- 기존 학교에 작성자 UID가 없다면 관리자 검토 후 백필하거나 관리자 전용 삭제를 허용하세요.
- 설정 본문, 학교 목록 인덱스 등 여러 데이터를 따로 저장한다면 트랜잭션/일관성 있는 작업으로 함께 삭제하세요.
- 삭제 후 Worker/CDN/KV 캐시 및 별도 목록 캐시도 무효화하세요. GET 응답에도 적절한 Cache-Control을 설정하세요.

완료 응답은 **`204 No Content`**, 또는 **`200`과 JSON `{ "deleted": true }`**를 권장합니다.
호환을 위해 `{ "success": true }`와 `{ "ok": true }`도 인식합니다.
`200` HTML, 빈 `200`, `202 Accepted`, 명시적인 실패 응답은 완료로 간주하지 않습니다.
프런트엔드가 성공 응답만 보고 목록을 제거하므로 실제 DB 삭제 완료 후 응답해야 합니다.

오류 권장 형식:

```json
{ "code": "FORBIDDEN", "message": "삭제 권한이 없습니다." }
```

| 상태 | 확인할 사항 |
| --- | --- |
| 401 | Firebase 토큰 만료/프로젝트 불일치/검증 실패 |
| 403 | 작성자 UID 누락 또는 관리자 UID 설정 불일치 |
| 404 | 존재하지 않는 학교인지, DELETE 경로 자체가 없는지 Worker 로그에서 구분 |
| 405 / 501 | DELETE 미허용 또는 미구현 |
| 5xx | DB 제약·연관 데이터·키 불일치·서버 예외 |
| 브라우저 네트워크 오류 | CORS, OPTIONS, 인증 헤더, 연결 실패 |
| 15초 초과 | 실제 삭제되었을 수도 있으므로 목록을 새로고침한 뒤 재시도 |

404는 라우트 미구현일 수도 있어 프런트엔드에서 삭제 성공으로 처리하지 않습니다.
멱등 삭제를 원하면 **인증·권한 검사 후** 이미 삭제된 리소스에 204를 반환하는 정책을 구현하세요.

## 2. CORS

허용하는 프런트엔드 origin에 대해 OPTIONS와 모든 성공·오류 응답에 CORS 헤더를 추가하세요.
예시:

```http
Access-Control-Allow-Origin: <허용된 프런트엔드 origin>
Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS
Access-Control-Allow-Headers: Authorization, Content-Type
Vary: Origin
```

origin은 허용 목록으로 검증하세요. 인증이 필요한 OPTIONS 요청으로 만들지 마세요.

## 3. 관리자 권한

현재 `VITE_MASTER_UID`는 관리자 UI 표시 여부만 결정합니다. 공개된 클라이언트 환경변수이므로
보안 권한 검증 수단이 아닙니다. Worker의 관리자 UID 허용 목록 또는 검증한 Firebase custom
claim이 실제 권한의 기준이어야 합니다. 양쪽 설정을 맞추세요.

이번 JSON 기능은 **관리자로 로그인한 사용자가 학교의 과목·평가계획을 파일로 가져오는 기능**입니다.
JSON 파일로 Firebase 계정을 만들거나 관리자 권한을 부여하는 기능은 아닙니다.

## 4. JSON과 선택 기간

- 관리자 → 학교 추가 → 학교·학년·학기 선택 → JSON 파일 선택 → 평가계획 선택 → 적용 → 배포.
- 첨부 파일과 같은 `[{ id, name, color, assessments, passOnly? }]` 형식을 지원합니다.
- 키 따옴표 생략, 마지막 쉼표, 이어진 여러 배열 또는 배열의 배열을 지원합니다.
- 파일에 학교 정보가 없으므로 선택한 학교·학년·학기에 한 평가계획씩 적용합니다.
- 파일은 브라우저에서 JSON5로 파싱·검증하고 실행하지 않습니다. 최대 1MB입니다.
- 파일 가져오기 자체는 서버 요청을 하지 않습니다. 배포 시 기존 publish/update API를 사용합니다.
- 평가 기간은 입력을 비워 두어도 됩니다. 배포 직전에 `1학기` 또는 `2학기` 문자열로 변환합니다.
  따라서 기존 서버가 비어 있지 않은 period를 요구해도 요청은 호환됩니다.
- API를 직접 사용하는 클라이언트도 지원하려면 서버에서 누락/공백 period를 `${semester}학기`로
  정규화하고, 과목/평가 ID의 유일성·반영비율 합계·원점수 미산출 과목 조건을 다시 검증하세요.
- `hideAssessmentDetails`는 프런트엔드에서 제거했습니다. 서버에서 필수로 검증하지 말고,
  저장된 이전 값은 무시하거나 마이그레이션 시 제거할 수 있습니다.

## 운영 검증

테스트용 학교로 작성자 삭제, 관리자 삭제, 타인 삭제 거절, 로그아웃 삭제 거절,
이미 삭제한 학교 재요청을 확인하세요. 삭제 후 페이지 새로고침 및 다른 브라우저에서도
목록·상세·공유 링크에 삭제가 반영되는지 확인해야 합니다. 다른 사용자의 로컬 캐시나
개인 점수까지 전역 삭제하는 기능은 이번 프런트엔드 변경에 포함되지 않습니다.
